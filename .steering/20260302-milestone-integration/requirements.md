# マイルストーンと記録の統合 - 要求定義

## 背景

記録（DailyLog）とマイルストーン（Milestone）が別々のページ・カテゴリ体系で管理されており、ユーザー体験が分断されている。記録のカテゴリに「成長」が含まれているにもかかわらず、マイルストーンが独自の5カテゴリを持つため冗長。マイルストーンを記録に付く「初めての出来事フラグ」として簡素化し、動線を統合する。

## 変更概要

### 1. マイルストーンの簡素化

マイルストーンを独立エンティティから「記録の付属フラグ」に変える。

- **入力**: トグルON + タイトル任意入力（カテゴリ選択を廃止）
- **タイトル**: ユーザーが自由に入力。空の場合は本文先頭30文字から自動生成
- **カテゴリ**: カラム廃止（記録のカテゴリで代用）
- **AI抽出**: 廃止（週次通信生成時のマイルストーン自動検出を削除。手動トグルのみ）
- **source/weekly_report_id**: 不要になるため廃止

### 2. マイルストーン一覧を /logs ページに統合

- /logs ページのフィルターに「初めての出来事あり」を追加
  - 既存カテゴリフィルターとの掛け合わせが可能（例: 「ことば」×「初めての出来事あり」）
  - マイルストーン付きログはAccentCard（amber）で視覚的に区別
- 統計ページからマイルストーン一覧（MilestoneTimeline）を撤去
  - 「成長」タブの「初めての出来事」サブタブを廃止

### 3. 統計ページの再構成

- **成長タブ**: 身長・体重グラフのみに絞る（サブタブ廃止）
- **記録タブ**: 既存の気分グラフ・カテゴリ円グラフに加え、「初めての出来事 N件」のサマリーカードを追加

### 4. カレンダーにマイルストーンマーク追加

- マイルストーン付きの日にスターマーク等を表示
- 一目で「初めての出来事があった日」がわかるようにする

### 5. DBスキーマ変更

milestones テーブルの簡素化:
- `category` カラム: 削除
- `source` カラム: 削除
- `weekly_report_id` カラム: 削除
- `memo` カラム: 削除（本文が記録側にあるため不要）
- 残るカラム: `id`, `child_id`, `daily_log_id`(NOT NULL化), `title`, `milestone_date`, `created_at`, `updated_at`
- 既存データ: `daily_log_id = null`（AI抽出分）のレコードを削除するマイグレーション

## 受け入れ条件

- [ ] ログフォームのマイルストーン入力がトグルのみになっている
- [ ] トグルON時にタイトル入力欄が表示され、空なら本文から自動生成される
- [ ] /logs ページで「初めての出来事あり」フィルターが動作する
- [ ] マイルストーン付きログがamberアクセントのカードで表示される
- [ ] 統計ページの成長タブが身長・体重のみになっている
- [ ] 統計ページの記録タブにマイルストーン件数サマリーが表示される
- [ ] カレンダーでマイルストーン付きの日にマークが表示される
- [ ] 週次通信生成時のAIマイルストーン抽出が削除されている
- [ ] DBマイグレーションで不要カラム・データが整理されている
- [ ] マイルストーン編集ダイアログが不要になり削除されている
- [ ] lint・型チェック・テストがすべて通る
