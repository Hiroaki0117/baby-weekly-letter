# 複数子供対応 - 要求定義

## 概要

現状1人の子供を前提としたアプリを、複数の子供に対応させる。
記録・通信・表示すべてを子供単位で管理できるようにする。

## ユーザーストーリー

### US-1: 子供の追加登録
- **As** 親ユーザー
- **I want** 家族ページから子供を追加登録できる
- **So that** 兄弟姉妹それぞれの記録を管理できる

### US-2: 子供を選んで記録
- **As** 親ユーザー
- **I want** 記録する際にどの子供のログかを選択できる
- **So that** 誰の記録かが明確になる

### US-3: 子供ごとの記録確認
- **As** 親ユーザー
- **I want** 記録一覧やカレンダーで子供ごとにフィルターできる
- **So that** 特定の子供の成長を振り返れる

### US-4: 子供ごとの通信生成
- **As** 親ユーザー
- **I want** 週次通信・月次まとめが子供ごとに個別生成される
- **So that** 子供それぞれの成長段階に合った内容を受け取れる

### US-5: 複数子供の月齢表示
- **As** 親ユーザー
- **I want** 今日のページで全員の月齢を確認できる
- **So that** 一目で子供たちの年齢がわかる

### US-6: オンボーディングでの複数登録
- **As** 新規ユーザー
- **I want** 初回登録時に複数の子供をまとめて登録できる
- **So that** セットアップを一度で完了できる

## 受け入れ条件

### データベース
- [ ] `daily_logs` に `child_id` カラムが追加されている
- [ ] `weekly_reports` に `child_id` カラムが追加されている
- [ ] `monthly_reports` に `child_id` カラムが追加されている
- [ ] 既存データは最初に登録された子供に自動割り当てされる
- [ ] `child_id` は NOT NULL（既存データのマイグレーション後）

### 今日ページ
- [ ] 子供が複数人いる場合、全員分の「名前 - ○歳○ヶ月」が表示される
- [ ] 子供が1人の場合は現状と同じ表示

### 記録フォーム
- [ ] 子供が2人以上の場合、フォーム上部に子供セレクタが表示される
- [ ] 子供が1人の場合、セレクタは非表示で自動選択される
- [ ] 同じ子供に対して1日複数記録が可能

### 記録カード
- [ ] どの子供の記録かを示すバッジが表示される

### 記録一覧
- [ ] 子供フィルターが追加されている（複数子供の場合のみ表示）

### カレンダー
- [ ] 記録カードに子供名バッジが表示される

### 通信
- [ ] 子供が複数いる場合、タブで子供を切り替えられる
- [ ] 子供が1人の場合、タブは非表示で現状と同じ
- [ ] 生成は「今見ている子供」の記録に基づいて行われる
- [ ] AIプロンプトに子供の名前・月齢が含まれる

### 家族ページ
- [ ] 登録済みの子供が一覧表示される
- [ ] 子供の追加ができる
- [ ] 子供の名前・生年月日の編集ができる

### オンボーディング
- [ ] 「＋ もう1人追加」ボタンで複数子供を登録できる
- [ ] 最低1人の登録は必須

## 制約事項

- 既存の1人子供ユーザーに破壊的変更を与えない
- 子供が1人の場合、UIの変更は最小限（セレクタ非表示など）
- マイグレーションは既存データを壊さない（nullable → データ埋め → NOT NULL の段階的移行）
