# 要求定義: カレンダービュー & 週次通信クオリティ改善

## 概要

本作業では2つの機能を実装する：

1. **カレンダービュー** — ログの振り返り体験を改善する月次カレンダー画面
2. **週次通信クオリティ改善** — AI生成通信の内容を「浅い・薄い」から「読み応えのある手紙」へ引き上げる

---

## 機能1: カレンダービュー

### ユーザーストーリー

> 親として、カレンダー上で過去のログを一覧し、特定の日をタップして詳細を確認したい。
> これにより「手帳をめくる」ような振り返り体験を得たい。

### 受け入れ条件

- [ ] ナビゲーションに「カレンダー」メニューが追加されている
- [ ] 月単位のカレンダーグリッドが表示される（月曜始まり）
- [ ] ログが存在する日にはその日の気分 emoji が表示される
- [ ] 1日に複数ログがある場合、ログ数バッジまたは複数 emoji が表示される
- [ ] 日付セルをクリックするとその日のログ一覧が展開/表示される
- [ ] 前月・次月へのナビゲーションができる
- [ ] モバイルで快適に操作できるレスポンシブデザイン
- [ ] 「手帳と封筒」デザインシステムに統合されている

### 制約

- 外部カレンダーライブラリは不使用（軽量に自前実装）
- date-fns で日付計算（既存の weekStartsOn: 1 と整合）

## 機能2: 週次通信クオリティ改善

### 課題分析

現在の通信は以下の問題を抱えている：

| 問題 | 原因 |
|------|------|
| ログの羅列的なまとめにしかならない | プロンプトが「抽出」指示に偏り、「解釈・考察」の指示がない |
| 毎回同じ印象の文章になる | 固定セクション構成が自由な表現を制限している |
| 深みや物語性がない | ログ同士のつながり・変化・文脈を読み取る指示がない |
| 字数が短すぎる | 350〜500字では掘り下げる余裕がない |
| 誰の通信か分からない | 子どもの名前・月齢などの背景情報がない |

### 改善方針

#### A. プロンプト改善

- **思考ステップ（Chain-of-Thought）導入**: 生成前に「今週のテーマ」「最も印象的な変化」を内部推論させる
- **構成の自由化**: 固定セクション（成長のきざし/かわいかった瞬間/...）を廃止し、LLMがログ内容に応じて最適な構成を選ぶ
- **文脈の注入**: 前回通信の要約 or 前週のハイライトを渡し、「先週からの変化」を語れるようにする
- **トーン指示の具体化**: 抽象的な「やさしく感動的に」→ 具体的な文体ガイドラインとサンプル文
- **字数拡大**: 500〜800字に拡大

#### B. 背景情報（プロフィール）の導入

- ユーザー設定画面で子どもの名前・生年月日を登録できるようにする
- プロンプトに名前・月齢を注入することで、パーソナライズされた通信を生成する
- 月齢に応じた成長の文脈を提供する（例: 「生後6ヶ月で○○ができるように」）

#### C. LLMモデルのアップグレード

- `gemini-2.0-flash` → `gemini-2.5-flash` に変更
- 2.0 Flash は 2026/3/31 に廃止予定、移行は必須
- 2.5 Flash は文章生成品質が向上しており、コスト・レイテンシーも実用的

#### D. 前回通信の文脈活用

- 生成時に前回の通信内容（直近1件）を取得
- プロンプトに含めることで、回をまたいだストーリーの連続性を実現

### 受け入れ条件

- [ ] プロフィール設定画面で子どもの名前・生年月日を登録できる
- [ ] 通信生成時にプロフィール情報がプロンプトに反映される
- [ ] 通信生成時に前回通信の内容がプロンプトに含まれる
- [ ] プロンプトが Chain-of-Thought + 自由構成 + 文体ガイドライン に改善されている
- [ ] LLMモデルが gemini-2.5-flash に更新されている
- [ ] 生成される通信が500〜800字程度の読み応えある内容になる
- [ ] 既存の通信生成・表示フローに破壊的変更がない

### 制約

- プロフィール情報は Supabase の新テーブル `profiles` に保存
- 子ども情報は v1 では1人分のみ対応（将来的に複数子ども対応可）
