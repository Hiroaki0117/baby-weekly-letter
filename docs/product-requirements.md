# プロダクト要求定義書

## 1. プロダクトビジョンと目的

### プロダクト名（仮称）

すくすく日記

### ビジョン

日々の育児の記録を簡単に残し、週に1回「ちょい感動系」の週次通信として自動生成することで、育児の成長と記憶を振り返れるようにする。

### 目的

- 入力負担を最小にし、継続的なログ記録を実現する
- ログを残すこと自体ではなく「思い出が生成されること」に価値を置く
- Webアプリ（PC/スマホ）で完結する

---

## 2. ターゲットユーザーと課題・ニーズ

### ターゲットユーザー

- 乳幼児の育児中の親（パパ・ママ）

### 課題

- 育児中は忙しく、日々の出来事を記録する余裕がない
- 記録しても振り返る機会がなく、記憶が薄れていく
- 育児日記は続かない（入力が面倒で挫折しやすい）

### ニーズ

- 最小限の入力で育児ログを残したい
- 自動的に振り返りコンテンツが生成されてほしい
- 子どもの成長を実感できる仕組みがほしい

## 4. 成功の定義

- 1週間分のログを入力できる
- ボタン操作で週次通信が生成される
- 週次通信が保存され、後から閲覧できる
- その週に紐づく写真を一覧表示できる

---

## 5. ビジネス要件

- 個人利用を前提とする（マルチテナントだがスケールは考慮しない）
- 運用コストを最小限に抑える（Supabase無料枠 + Vercel無料枠 + Gemini API低コスト）

## 6. ユーザーストーリー

### US-1: 日次ログ登録

> 育児中の親として、今日の出来事と気持ちを簡単に記録したい。それにより、後から振り返れるようにしたい。

### US-2: 日次ログ参照・編集

> 育児中の親として、過去に登録したログを確認・修正したい。それにより、正確な記録を残せるようにしたい。

### US-3: 週次通信生成

> 育児中の親として、1週間の育児ログから自動で週次通信を生成したい。それにより、手間なく振り返りコンテンツを得たい。

### US-4: 週次通信参照

> 育児中の親として、過去の週次通信を一覧で見たい。それにより、子どもの成長を時系列で振り返りたい。

### US-5: 写真の週次表示

> 育児中の親として、週次通信と一緒にその週の写真を見たい。それにより、文章と写真の両方で記憶を振り返りたい。

### US-6: 写真ギャラリー（v2）

> 育児中の親として、過去に撮った写真を月別で一覧で見たい。それにより、子どもの成長を写真で振り返りたい。

### US-7: 過去の振り返り（v2）

> 育児中の親として、○年前の同じ日の記録を自動で見たい。それにより、成長の変化を実感したい。

### US-8: 統計ダッシュボード（v2）

> 育児中の親として、記録の傾向やパターンをグラフで見たい。それにより、育児の全体像を把握したい。

### US-9: 家族間のリアクション（v2）

> 育児中の親として、パートナーの記録にスタンプで反応したい。それにより、「見てるよ」の気持ちを伝えたい。

### US-10: 通信エクスポート（v2）

> 育児中の親として、週次・月次通信をPDFや画像で保存したい。それにより、祖父母へのLINE共有や印刷用途に使いたい。

### US-11: 身長・体重記録（v3）

> 育児中の親として、子供の身長・体重を記録して成長曲線で見たい。それにより、成長の推移を数値で実感したい。

### US-12: 週次通信カスタマイズ（v3）

> 育児中の親として、週次通信の文体やセクション構成を自分好みに変えたい。それにより、より自分たちらしい通信を受け取りたい。

### US-13: 成長タイムライン（v3）

> 育児中の親として、子供の「初めて○○した」をまとめて見たい。それにより、成長の節目を一目で振り返りたい。

### US-14: 家族コメント（v3）

> 育児中の親や祖父母として、記録にコメントを残したい。それにより、スタンプだけでなく言葉でも気持ちを伝えたい。

### US-15: 体温記録（v3）

> 育児中の親として、子供の体温を記録してグラフで推移を見たい。それにより、体調の変化を早期に把握したい。

### US-16: 記録リマインダー（v3）

> 育児中の親として、日記を書き忘れた日に通知してほしい。それにより、記録の習慣を維持したい。

### US-17: 音声入力（v4）

> 育児中の親として、話すだけで日記を入力したい。それにより、両手がふさがっていても記録を残せるようにしたい。

### US-18: 年次アルバム自動生成（v4）

> 育児中の親として、1年分の記録からAIで年間ダイジェストを自動生成したい。それにより、1年の成長を一冊のアルバムとして振り返りたい。

### US-19: 睡眠・食事かんたんトラッキング（v4）

> 育児中の親として、睡眠時間や食事量をワンタップで記録したい。それにより、生活リズムの傾向を把握したい。

## 7. 受け入れ条件

### AC-1: 日次ログ登録

- フリーテキスト（必須）、気分スタンプ（必須）、カテゴリ（任意・複数選択）、写真（任意・1枚）を入力して保存できる
- 同一日に複数件のログを登録できる
- 保存後、登録内容が即座に参照画面に反映される

### AC-2: 日次ログ参照・編集

- 過去のログを日付単位で参照できる
- 登録済みのログを編集・更新できる

### AC-3: 週次通信生成

- 「今週の通信を作る」ボタンで週次通信を生成できる
- 生成される通信は固定フォーマットに従う
- ログにない内容が含まれていない
- 文字数は350〜500字程度
- 同一週の再生成は上書き保存される
- 週の定義は月曜〜日曜

### AC-4: 週次通信参照

- 過去の週次通信を一覧表示できる
- 一覧から選択して詳細表示できる

### AC-5: 写真の週次表示

- 週次通信詳細画面にその週に登録された写真が一覧表示される

## 8. 機能要件

### 8.1 日次ログ登録機能

#### 入力項目

| 項目 | 必須 | 型 | 備考 |
|------|------|-----|------|
| 対象の子供 | 必須 | uuid | 子供が1人の場合は自動選択 |
| フリーテキスト | 必須 | string | 今日の出来事＋気持ち |
| 気分スタンプ | 必須 | enum | 🥰 / 🙂 / 😐 / 😴 / 😭 |
| カテゴリ | 任意 | string[] | 複数選択可 |
| 写真 | 任意 | file | 1ログにつき1枚 |

#### カテゴリ一覧

- 食事
- 睡眠
- 遊び
- ことば
- 運動
- 体調
- 成長
- パパ/ママの気持ち

### 8.2 週次通信生成機能

#### 生成条件

- ユーザー操作（ボタン押下）による生成
- 対象期間：該当週の月曜〜日曜のログ
- LLM: Google Gemini 3.8 Flash
- 生成は Next.js Route Handler 経由で実行

#### 出力フォーマット

```
📮 今週のすくすく日記（YYYY/MM/DD〜YYYY/MM/DD）

（本文：今週の出来事を自然な文章でまとめる）

🌱 成長のきざし
・
・

😊 かわいかった瞬間
・

🫧 ちょっと大変だったこと
・

🧡 パパ/ママのひとこと
（1〜2文）

（最後は必ず前向きな一文で締める）
```

#### AI生成仕様

- 日本語で出力する
- 文体はやさしく、少し感動的にする
- ログにない出来事を推測して書かない
- 読みやすく短い段落と箇条書きを混ぜる
- 出力は固定フォーマットに従う
- 文字数は350〜500字程度

## 9. 非機能要件

### 9.1 技術スタック

| 領域 | 技術 |
|------|------|
| フロントエンド | Next.js + Tailwind CSS + shadcn/ui |
| フォーム | React Hook Form + Zod |
| 日付操作 | date-fns |
| バックエンド | Supabase (Auth / Database / Storage) |
| API | Next.js Route Handlers |
| LLM | Google Gemini 3.8 Flash |
| デプロイ | Vercel |
| 認証方式 | メール+パスワード / Google OAuth |

### 9.2 セキュリティ

- 全テーブルにRLS（Row Level Security）を設定
- `my_family_id()` 関数により家族単位でアクセス制御
- APIキーはサーバーサイド（Vercel環境変数）で管理

### 9.3 データ設計

| カラム | 型 | 備考 |

| id | uuid | PK |
| family_id | uuid | FK → families |

| author_id | uuid | FK → auth.users（記録者） |
| log_date | date | ログ対象日 |
| text | text | フリーテキスト |
| mood | text | 気分スタンプ（moved / happy / neutral / tired / sad） |

| photo_storage_path | text | 写真のStorageパス（任意） |
| created_at | timestamptz | |
| updated_at | timestamptz | |

※ 同一日・同一子供に複数件登録可能（unique制約なし）

| カラム | 型 | 備考 |

### 9.4 Storage設計

- バケット名: `log-photos`

### 10.9 設定画面（MVP）

- プロフィール編集
- ログアウト

### 10.10 モバイルナビゲーション（v2.6 予定）
